# 07 · 页面层设计（原生页 + 内嵌页 + 跳转）

> 前置：`06-登录方案与客户端架构`。本文只谈"页面怎么做"，含数据源、交互、异常态。
> 原则：**能用 API 的原生做，能免登的内嵌做，打不开的跳出去。** 不做第四种。

---

## 一、信息架构

```
底部 5 Tab
├── ① 今日        ← 打开率最高的页面，一屏看完"我现在要干什么"
├── ② 课表        ← 周视图 + 下一节课，原生渲染（复用 KechTable）
├── ③ 服务        ← 门户 163 应用的收敛入口（原生宫格 + 内嵌/跳转分流）
├── ④ 通知        ← 学校公告 + 门户待办/消息 聚合
└── ⑤ 我的        ← 个人信息、成绩/考试、设置、登录态
```

**为什么是这个结构**：学生一天里 80% 的动作是「看今天要干嘛」→「看课表」→「找一个服务」→「看有没有新通知」。成绩/考试虽然重要但低频，放二级。

---

## 二、原生页面（A 形态）

### ① 今日（Home）

| 区块 | 内容 | 数据源 | 缓存 |
|---|---|---|---|
| 顶部条 | 日期、农历、教学周（第 N 周）、天气 | `/card/weather/getWeatherAndDate` | 6h 本地缓存 |
| **下一节课卡** | 课程名、教师、地点、剩余时间倒计时、进度条 | 本地课表库（编译期算） | 离线可用 |
| 今日课程 | 今天 3–6 节课，按时间轴排，已上完的置灰 | 本地课表库 | 离线可用 |
| 待办角标 | 待办数 + 前 2 条标题 | `/task/getTaskInfo` | 15min |
| 通知摘要 | 最新 3 条公告 | 公开抓取（见 ④） | 30min |
| 快捷宫格 | 8 个常用：查成绩 / 考试 / 空教室 / 一卡通 / 报修 / 图书馆 / BB / 更多 | 静态配置 + 远程可覆盖 | 7 天 |

**交互**：
- 点「下一节课卡」→ 跳课表并定位到该课
- 下拉刷新只刷「待办 + 通知 + 天气」，不动课表
- 长按快捷宫格 → 进入编辑（增删排序）

**异常态**：
- 未登录：显示课表（本地）+ 通知（公开），待办区显示「登录后查看」
- JWT 过期：静默续期；续期失败 → 顶部灰色条「登录已过期，点此重新登录」，**不弹模态框打断**

### ② 课表

| 视图 | 说明 |
|---|---|
| 周视图（默认） | 7 列 × 12 节，课程块按节次高度绝对排版（**不要按"两节一组"分组**，否则 3–5 节的课会重复渲染——这是 KechTable 踩过的坑） |
| 学期周切换 | 左右滑或顶部分段控件，非本周课程降透明度 |
| 课程详情 | 点击弹出：课程名/教师/地点/周次/学分/课程性质/课程编号 |
| 桌面小组件 | 今日课程 + 下一节课倒计时（**原生核心增量**） |

**数据源**：`jw.bucm.edu.cn/jsxsd/xskb/bzyXskbList` 的 `table.layui-table`（行数最多那张，32 行×10 列），时间编码 `30102` = 周三第 1–2 节。

**更新策略**：登录后首次拉取 → 存本地 → 每周一后台静默刷新一次 → 手动下拉强制刷新。

### ③ 服务（应用中心收敛）

这是「页面层要做多一点」的重点：**163 个应用不能平铺，要重排**。

```
服务页结构
├── 搜索框（本地索引 163 应用名 + 979 服务名）
├── 我常用（按使用频次自动排序，最多 8 个）
├── 分组（不按学校的"教学科研/资产财务…"，按学生视角重排）
│   ├── 学习     教务 / BB / 轻新课堂 / 题库考试 / 微课堂 / 图书馆
│   ├── 办事     一表通（按场景再分：证明 / 奖助 / 学籍 / 住宿）
│   ├── 生活     一卡通 / 缴费 / 报修 / 网络 / 校医院
│   └── 其他     云盘 / 正版软件 / 邮箱 / 就业
└── 应用详情页（每个应用一个统一模板，见下）
```

**应用详情页模板**（统一，163 个共用）：
- 图标 + 名称 + 归属部门 + 分类
- 「打开」按钮 → 按 `06` 的三分表分流：
  - 有移动端地址且可嵌 → **内嵌 WebView**
  - 微信专属 → **跳企微**（按钮文案写「在微信中打开」）
  - 只有 PC 地址 → 「复制链接 / 在浏览器打开」
- 「加入常用 / 取消」
- 「这是什么」：一句话说明（来自 979 服务的指南标题）

### ④ 通知

| 子 Tab | 数据源 | 说明 |
|---|---|---|
| 学校公告 | `www.bucm.edu.cn/tzgg/index.htm` | 当前仅 11 条无分页 |
| 新闻 | `www.bucm.edu.cn/xwgl/index{N}.htm`，N=0..85 | 约 1720 篇，可全量抓，**零登录** |
| 门户待办 | `/task/getTaskInfo` | 需 JWT |
| 门户消息 | `/bucm/message/getsendMsgQX` | 需 JWT |

**关键**：公告/新闻是公开数据，**未登录也能看** —— 这是首版最有价值的"零门槛"功能，也是审核员能理解的"内容型 App"部分。

**交互**：列表虚拟滚动、已读标记本地存、支持按「教务处 / 学生处 / 图书馆 / 学院」筛选（按来源部门）。

### ⑤ 我的

- 个人信息卡：头像、姓名、学号、院系（**从 JWT payload 解出，不额外请求**）
- 成绩 / 绩点（二级页）
- 考试安排（二级页）
- 空教室（二级页）
- 设置：登录状态、清除缓存、关于、隐私政策、非官方声明

**⚠️ 隐私**：JWT 里有 `id_number`（身份证号）、`mobile`、人脸照片地址。**这些一律不展示、不落日志、不进埋点**。头像地址可以用，但换成自建缓存。

## 三、二级原生页

### 成绩页
- 数据源：`jw.bucm.edu.cn/jsxsd/kscj/cjcx_frm` → `cjcx_query` → `cjcx_list`（**HTML 表格，不是 JSON**）
- 展示：按学期折叠、学分绩点计算、挂科标红、导出图片
- 缓存：本地存一份，避免每次重解析

### 考试安排
- 数据源：`/jsxsd/xsks/xsksap_query` → `xsksap_list`
- 展示：日历视图 + 倒计时 + 「N 天后」
- 提醒：本地通知（考前 3 天 / 1 天 / 2 小时）

### 空教室
- 数据源：`/jsxsd/view/kbxx/kbcx/llsykb_frm.jsp`
- 展示：按教学楼/时段查空闲教室
- 注意：**数据非实时**，页面要标注「数据更新于 xx:xx」

### 校历
- 数据源：本地内置（当前官方校历页只更新到 2024 年，不可依赖）
- 展示：学期起止、假期、考试周、教学周对照

## 四、内嵌 WebView 页面（B 形态）

**统一容器 `EmbedWebView` 需要做 5 件事**：

1. 共用持久化 cookie 仓（与登录 WebView 同一个 `WKWebsiteDataStore` / `CookieManager`）
2. 顶部原生导航栏：返回、刷新、更多（复制链接 / 浏览器打开）
3. 进度条 + 加载失败重试 + 离线提示
4. 域名白名单（只允许 `*.bucm.edu.cn` + 已知外链域）
5. **登录态探针**（注入 JS 判断是否被踢回登录页）

| 内嵌页 | 地址 | UA | 要特别处理的 |
|---|---|---|---|
| **BB 课程平台** | `bb.bucm.edu.cn` | 移动 UA | 任意路径都返回 200 登录页 → 必须 JS 探针判登录；SSO 走 CASTGC |
| **深度辅导** | `sdfd.bucm.edu.cn` | 移动 UA | 唯一真响应式，`viewport-fit=cover`，支持 iOS 安全区 |
| **智慧后勤（报修）** | `zhhq.bucm.edu.cn/wx/#/basicHome` | 移动 UA | 可能依赖微信 JS-SDK 的定位/扫码，需实测 |
| **一表通** | `workflow.bucm.edu.cn/v2/matter/detail?id=xxx` | 移动 UA | 133 个流程按 id 直达；40 个有 `m_` 移动路由 |
| **图书馆** | `slib.bucm.edu.cn` | 移动 UA | 超星 Vue SPA，先内嵌整站，二期再谈接口 |
| **云盘** | `cloudpan.bucm.edu.cn` | 移动 UA | — |

**为什么 BB 值得内嵌而不是跳转**：学生每天看课件/交作业，跳出会切断使用。而 BB 是响应式的，SSO 也通，内嵌体验可接受。

## 五、跳出（C 形态）

| 入口 | 目标 | 实现 | 文案 |
|---|---|---|---|
| 一卡通余额/充值 | 企业微信 e卡通 | `wxwork://` 或通用链接 | 「在微信中打开」+ 二次说明 |
| 缴费 | 企业微信 → jiaofei | 同上 | 同上 |
| 教务移动端 | 企业微信 | 同上 | 同上 |
| 采购 | 企业微信 | 同上 | 同上 |
| 轻新课堂 | 系统浏览器 | `UIApplication.open` / Intent | 「此服务仅支持浏览器访问」 |

**跳出页的体验设计**（不能只是弹个 toast）：
- 跳出前给一个说明页：图标 + 一句「该服务由学校企业微信提供，将为你打开微信」
- 提供「复制链接」兜底
- 返回 APP 后，如果该服务有数据（如一卡通余额）——**没有**，别假装有

## 六、登录态 × 页面状态矩阵

| 页面 | 未登录 | JWT 有效 | JWT 过期 |
|---|---|---|---|
| 今日 | 课表(本地)+公告，待办区提示登录 | 全量 | 灰条提示 + 静默续期 |
| 课表 | 本地缓存（若曾登录过）或空态引导登录 | 正常 | 用缓存，后台续期 |
| 服务 | 显示全部应用，点击时提示登录 | 正常 | 正常（应用清单可缓存） |
| 通知 | **公开公告/新闻正常**，待办区提示登录 | 全量 | 公告正常，待办提示 |
| 我的 | 登录引导页 | 信息卡 | 灰条 + 重新登录 |
| 内嵌页 | 打开即 CAS 登录页（正常，用户可当场登） | SSO 免登 | 同左 |

**设计原则**：**未登录不是"空白 App"**。课表（若有缓存）、公告、新闻、校历、服务目录全部可用 —— 这既是体验，也是审核时证明"本 App 有独立价值"的证据。

## 七、全局交互规范

| 项 | 规范 |
|---|---|
| 刷新 | 下拉刷新（原生页）；WebView 用顶部刷新按钮 |
| 空态 | 必须区分「未登录」「无数据」「加载失败」三种，文案不同 |
| 错误 | 网络错误给重试按钮，不弹模态框；不暴露任何技术错误码给用户 |
| 登录过期 | 全局统一拦截，**同一时刻只允许一个登录流程** |
| 深链 | 支持 `ubcm://course/{id}`、`ubcm://notice/{id}`，便于通知点击跳转 |
| 深色模式 | 跟随系统 |
| 字号 | 支持系统动态字体（课表网格除外） |
| 离线 | 课表、公告历史、校历完全离线可用 |

## 八、首版（MVP）页面范围

**做**：今日、课表（周视图）、通知（公开）、我的（登录+信息）、服务（宫格+内嵌分流）
**缓做**：成绩、考试、空教室（P1，需教务 HTML 解析）
**不做**：一卡通原生、缴费原生、133 个一表通流程重做、校园社交

**MVP 的成功标准**：一个同学装完，**不登录也能看到今天的课和最新公告**；登录一次后，能看到待办和成绩。
