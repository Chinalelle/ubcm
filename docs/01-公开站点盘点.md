## 1. 官网 www.bucm.edu.cn

### 1.1 技术底座

```http
HTTP/1.1 200 OK
Server: nginx
Content-Type: text/html
Content-Length: 82836
Last-Modified: Thu, 19 Nov 2026 01:11:05 GMT
ETag: "6afe4ca9-14394"
Accept-Ranges: bytes
```

- **纯静态 Nginx 直出**：`Last-Modified` + `ETag` + `Accept-Ranges` 三件套说明是磁盘上的静态 `.htm` 文件，不是动态应用。
- 存在 **CMS 后台痕迹**：`/cms/web/writeLog.jsp?siteID=3`、`/cms/web/search/index.jsp`、`/publish/gPublic/all.js`，`siteID=3`。这是高校「网站群」CMS 的典型路径结构（发布端出静态页、后台走 `/cms/web/*.jsp`）。
- 前台页面是**发布后的静态快照**，所以抓取成本极低，无需 cookie/登录。

## 2. 重点：通知公告的数据是怎么来的？

### 2.1 结论先行

**HTML 直出，没有 JSON 接口。** 列表与正文都在服务端渲染好的静态 `.htm` 里，`curl` 拿到的字节里就有全部标题与链接，无需执行 JS。

### 2.2 证据

列表页 `https://www.bucm.edu.cn/tzgg/index.htm`（HTTP 200，29295 B）中，公告条目直接以 HTML 结构呈现：

```html
<ul class="gp-avg-sm-2">
  <li><a class="item" href="b2b8d886c14a4a02a3a465c782fee7c1.htm">
      <div class="time">
        <div class="day fs42">19</div>
        <div class="month fs16">2025-10</div>
      </div>

```

> 注意：日期被**拆成了两个字段**——`day` 只有「日」，`month` 是「年-月」。APP 解析时需拼接 `2025-10` + `19`。

### 2.4 站内搜索：需 POST + CSRF token（不可直接 GET 复用）

`action="/cms/web/search/index.jsp"` 的表单为 `method="post"`，且引入了一个动态 token 脚本：

```html
<form name="searchForm" action="index.jsp" method="post" onsubmit="return verifyForm()">
  <script type="text/javascript" src="token.jsp"></script>
  <input type="hidden" name="siteID" value="3"/>
  <input type="hidden" name="channelID" value=""/>
  <input type="hidden" name="searchScope" value="0"/>
```

- GET `?siteID=3&keywords=通知` 返回的是**搜索页外壳 HTML**（还带若干空行前缀），不是结果数据。
- 有 `token.jsp` 反 CSRF 机制 → **按约束未提交表单验证**，APP 侧不建议依赖站内搜索，自己建索引更稳。

  var websiteId = 204163;
  var jsonId = 371490;
  var p_wfwfid = 2178;
  var sversion = '783807706d5d9b4933b4cddda69a59a73025';

### 4.2 内容接口：给的是 Vue 模板，不是数据

`https://slib.bucm.edu.cn/page/ck/peking_library` → 200，10320 B，`Content-Type: text/html;charset=UTF-8`。

打开只有 Vue 模板占位：

```
{{item.name}}  |  {{index>10 ? index : '0'+(index+1)}}  |  {{nav.name}}
```

`<title>智慧门户</title>`，`<body class="responsive-page">`。

- **结论：图书馆首页数据须执行 JS 后由后端 API 填充，纯 curl 拿不到栏目结构与书目数据。** 由于约束「不做爆破」，未继续枚举超星内部 API 路径；若要接入需在浏览器 DevTools 抓真实 XHR（建议交给有登录态的 Lead 或做一次带 headless 的单页 XHR 观测）。

### 4.3 顺带记录

- 内网 IP `10.110.228.147` 出现在前端变量 `rqIp` 中，说明该门户部署在校园内网段、由反代对外。
- `website_fid_login=1`、`mh_sign` 等 cookie 说明有独立的会话/签名体系，但不是身份登录态（`isLogin = false`）。

## 10. 对 APP 开发的可复用性结论

### 10.1 可直接用于 APP（免登录、纯静态、成本最低）

| 数据源 | 接口形态 | 建议 |
|---|---|---|
| **新闻流** `xwgl/index{N}.htm` | HTML 直出，N=0..85，每页 20 条，共约 1720 篇 | **首选**。APP 端直接正则/HTML 解析；建议服务端做抓取+结构化缓存，别让客户端直连（避免频繁请求被限速） |
| **通知公告** `tzgg/index.htm` | HTML 直出，11 条单页 | 直接解析。注意日期是 `month`(年-月) + `day`(日) 拼接 |
| **要闻 / 媒体 / 岐黄学术 / 人才培养 / 科研** `bzyyw`、`mtbzy`、`bzyr`、`rcpy`、`kxyj` | 同构静态 HTML | 统一写一个栏目适配器即可 |
| **文章详情** `{栏目}/{hex}.htm` | 含 `<meta name="PubDate">`、`class="article"/"content"` | **极佳**：元数据规范，正文容器稳定，富文本图片用相对路径需补域名 |
| **院系名录** `zzjg1/jxjg1/index.htm` | HTML 列表，16 个学院 | 可做「院系导航」静态配置表，一次抓取长期复用 |
| **教务处通知** `jxw.bucm.edu.cn/tz/index.htm` | 同构静态 HTML | 学生关心的教务通知，可与官网公告合并成一个「通知中心」 |
| **全媒体平台** `qmtpt/index.htm` | 静态 HTML + 可翻页 | 微信推文聚合，适合做「校园动态」信息流 |

**落地建议**：官网是「静态文件服务器」，**没有反爬、没有签名、没有频率令牌**，最稳的架构是——自建一个轻量抓取服务（定时 5~15 分钟一轮），把 HTML 解析成 JSON 落库，APP 只读自家 JSON。这样既避免给学校服务器造成压力，也不受页面改版影响（解析层可独立修）。

### 10.2 必须走登录态（免登录拿不到，本项目须另议）

| 数据源 | 原因 |
|---|---|
| **教务处 jw.bucm.edu.cn**（课表/成绩/考试/选课） | 强智 QZ 平台，全站登录态；公开面只有「栏目介绍」与「子系统链接」，无任何学生数据 |
| **Blackboard bb.bucm.edu.cn**（课程/作业/资源/成绩） | 首页即登录页，`bb-sso-BBLEARN` SSO；且 404 兜底成 200，无法做公开探测 |
| **WebVPN 后的所有校内资源** | 需 CAS / 微信 / 短信 / TOTP 多因子认证 |
| **图书馆 slib.bucm.edu.cn**（借阅、座位、电子资源） | 首页是超星 Vue SPA，数据靠 XHR；栏目 API 未在公开 HTML 中暴露 → **需带 JS 引擎观测 XHR 才能定接口**（本次受「不做爆破」约束未继续） |
| **数字北中医 i.bucm.edu.cn** | 301 到 `/tp_nup/` 登录门户（`<title>loading</title>`），全部内容在登录后 |
| **岐黄智 qhz.bucm.edu.cn** | 公网仅 Nginx 默认页；`/api/` 超时 → 疑内网或经 WebVPN 访问 |

### 10.3 对 APP 架构的三条硬约束

1. **iOS ATS 风险点已明确**：`http://qxkt.bucm.edu.cn:88/ve`、`http://jy.bucm.edu.cn`、`http://202.204.32.22/jypx` 均为 **HTTP 明文**。若 APP 要内嵌 WebView 打开，必须在 `Info.plist` 配 `NSAppTransportSecurity` 例外，且**上架 App Store 时会被审核问询**。非标端口 `:88`、`:5443` 同样要单独声明。
2. **没有官方 App、没有 m 站 → 品牌与入口都是空白**：本项目不存在「替代官方 App」的定位风险，反而可以成为第一个官方移动端。但同时也意味着**没有可借鉴的既有移动端交互规范**，需从头设计。
3. **登录态是唯一真正的门槛**：所有「学生个性化数据」（课表、成绩、考试、作业、借阅、通知已读）都必须复用学校 CAS/统一身份认证。APP 侧不要自建账号体系，应设计为 **CAS/WebVPN 微信扫码 + token 中继** 模式；具体可行性与合规性需 Lead 从 `i.bucm.edu.cn` 登录态侧给出结论。

### 10.4 待补的调研缺口（交给后续）

| 缺口 | 原因 | 建议下一步 |
|---|---|---|
| 图书馆超星的真实数据 API | 需执行 JS 才能触发 XHR | 用 headless（Playwright/CDP）打开 `slib.bucm.edu.cn` 抓 Network，或让有登录态的 Lead 抓 |
| 微信公众号的**具体名称与微信号** | 官网只有二维码位图，无文字 | 人工查看 `/gfwx/index.htm` 二维码，或从 `mp.weixin.qq.com` 推文页反查公众号名 |
| 是否存在小程序 | 公开 HTML 中无任何小程序 ID | 微信搜一搜「北京中医药大学」确认 |
| qhz 岐黄智的真实形态 | 公网只有默认页 | 在内网/WebVPN 环境下访问确认 |
| CMS 搜索接口的可用性 | 有 `token.jsp` 反 CSRF，按约束未提交表单 | 若确需搜索能力，用浏览器手动搜一次抓完整请求 |
