## 一、项目是什么

给北京中医药大学学生做的 **iOS/Android 校园 App**（ubcm）。
目标不是"再造一个门户"，而是把学生每天要用的 7 件事收敛到一屏：课表、通知、待办、成绩、考试、**一卡通余额/流水**、服务入口。

**已确定的形态**：本地优先的个人工具 —— 数据只存本机，不代登录、不集中托管、不对外提供服务（合规上唯一低风险路径，详见 `05-可行性与合规.md`）。

## 四、关键技术结论（**别再重新调研，直接用**）

### 4.1 门户 API

```
POST https://i.bucm.edu.cn/apim/sems-tp-nup/<模块>/<方法>
Content-Type: application/json
Authorization: Bearer <JWT>        ← 只认这个头，不认 cookie
→ {code, msg, data, errorData}
```

- JWT 存在 cookie `accessToken`，**有效期 4 小时**
- 少数接口免鉴权（如 `getUnitType`）
- **响应包装有 4 套**：`{code,msg,data}` / `{code,message}` / `{code:0,...}` 未鉴权 / Spring 原始 404；另有接口裸返回（详见 08）

### 4.2 教务（两套会话的关键）

```
课表真身（不是 HTML！）：
POST https://jw.bucm.edu.cn/jsxsd/xskb/loadSkzccx
Body: zc=                      （空=全部周次）
→ {"lstJx0415zb":[节次时间],"lstKb":[34条排课]}
字段：kcmc 课名 | jg0101mc 教师 | jx0601mc 教室 | kkzcmx 周次 | kcsj 时间编码 | ktmc 班级
时间编码：kcsj="30102" → 周三 第1、2节（第一位星期，之后每两位一节）

会话获取：GET https://cas.bucm.edu.cn/cas/login?service=https://jw.bucm.edu.cn/
         （有 CASTGC 会自动回跳，建立 jw 域的 JSESSIONID）
⚠️ 直接访问 /jsxsd/xxx 会落到强智登录页，不自动跳 CAS
```

成绩：`POST /jsxsd/kscj/cjcx_list`（表单，`kksj=&kcxz=&kcmc=&xsfs=all`）→ HTML 表格 17 列

### 4.3 一卡通（本次最大成果）

```
入口（不在菜单里，在门户首页组件）：
  https://ykt.bucm.edu.cn/servicehall/sso/login
  → CAS 单点（同一个 CASTGC）→ Set-Cookie: servicehall=...; Path=/servicehall
  → 落地页 HTML 隐藏字段 <input id="openid" value="...">

取数：
POST /servicehall/business/thirdQuerSelfTrade?openid=<openid>
{"starttime","endtime","tradetype":"-1","datetype":"1","pageNumber":0,"pageSize":20,"idserial":"<学号>"}

响应是加密的：{"data":"<前16位是key><密文>"}
解密：AES/ECB/PKCS5，key = data.substring(0,16)，密文 = 剩余部分 base64
明文：resultData.rows[].mername(商户) / txamt(分,负数为消费) / balance(分,余额) / txdate(ms)
```

## 六、六个坑（都踩过，别重蹈）

| # | 坑 | 真相 |
|---|---|---|
| 1 | `adb shell` 把参数拼成一条命令再解析 | cookie 里有 `;` 会被当命令分隔符 → **凭证一律 base64 传** |
| 2 | 教务页底部有「湖南强智科技」版权 | 拿它当登录页标志会误判 → 只认 `<title>登录</title>` / `请先登录系统` |
| 3 | 课表页 51 KB 但只有 4 个 `<tr>` | 数据是 JS 拉的 JSON，不是 HTML 直出 |
| 4 | 一卡通不在任何菜单里 | 在门户**首页组件库**（`sceneData` → `SCENE.WIDGET`），当前布局未启用 |
| 5 | `servicehall` cookie 的 Path 是 `/servicehall` | 访问 `/servicehallindex`（少斜杠）会掉登录 |
| 6 | 一卡通接口返回 `{"data":"..."}` | AES 加密，key 在密文前 16 位（REA 定位到 `dkywwachat.js:367`） |

KEY_HEX = "77726476706e69737468656265737421"
encode(host) = KEY_HEX + hex(AES-128-CFB(host, KEY, KEY))

### 10.5 WebView 登录器（已做）

`LoginWebViewActivity.kt` —— 通用 WebView 登录，三个目标：

| 目标 | 打开地址 | 抓取 cookie |
|---|---|---|
| 数智北中医 | `cas/login?service=.../tp_nup/` | `accessToken` |
| 一卡通 | `ykt.bucm.edu.cn/servicehall/sso/login` | `servicehall` |
| 图书馆座位 | `kjyy.bucm.edu.cn/` | `ic-cookie` |

实现要点：
- 进入前先把已有 `CASTGC` 写进 WebView 的 cookie 罐，CAS 会话还在就能直接过
- 每 1 秒轮询 `CookieManager.getCookie(url)`，抓到目标 cookie 就存进 Session 并亮出「完成」
- 4 分钟超时；UA 去掉 `; wv` 避免站点识别 WebView

**实测**：点「图书馆座位」→ WebView 自动 SSO → 显示「已获取 ic-cookie」→ 完成后体检，
座位组 4/4 全绿（楼层空位 2622/2622、全馆 2685 座、无违规）。

「URL 缓存」预热机制已破解 —— 先 `GET /authcenter/toLoginPage?redirectUrl=.../ic-web//auth/token?uuid=<32hex>&extInfo=<前10位>`，
再走 CAS，4 步跳转可达 `auth/token`（详见 `13-图书馆座位模块.md` §3.1）。
