## 二、三个设计决定（每个都是取舍，不是随手选的）

### 2.1 按节次等高等距，不按真实时间比例

真实作息里节与节的空档极不均匀：

| 空档 | 时长 | 原因 |
|---|---|---|
| 2→3 节 | 30 分 | 大课间 |
| **4→5 节** | **90 分** | 午休 |
| 6→7 节 | 30 分 | 大课间 |
| **8→9 节** | **60 分** | 晚饭 |
| 10→11 节 | 10 分 | 小节间 |

按时间比例画，午休吞掉三分之一屏、晚饭再吞一块，晚上两节课会被压成一条线。
所以**每节固定 46dp + 节间 4dp**，整表 12 行 = 596dp（手机一屏多一点）。

### 2.2 跨节块占 `end − start + 1` 个行高

这是「不能按两节一组分组」的落地方式。真实课表里同时存在
1 节（大学英语第 10 周）、1–2 节、1–3 节（中医基础学周一）、1–4 节（正常人体学Ⅰ）、
5–7 节（中医基础学周三）。按大节分组会把 1–3 切成「1–2」「3」两块。

几何只有三个函数（`WeekGeometry`）：

```
topOf(p)            = (p − 1) × (row + gap)
heightOf(start,end) = span × row + (span − 1) × gap
totalHeight(n)      = n × row + (n − 1) × gap
```

**有单测逐一验证「块的底边 == 末节格子的底边」**（1–12 节全部组合）。
这条断言是为了防「块比格子高一点/矮一点」的错位，肉眼很难发现但一眼看上去就是不齐。

### 2.3 周次默认跟随今天，手动翻走后停住

`pinnedWeek: Int?` —— `null` 表示跟随（每次 ticker 重算都回到当前周），
非 `null` 表示用户已经翻走了，**不要再把他拽回来**。
这样「每周一早上打开 App 自动是本周」和「翻到第 3 周查课不被 ticker 弹回」两件事同时成立。

## 三、同天冲突分栏

同一门课不同周次的不同地点、调课补课，会让同一天同一节次出现两条记录。
叠着画必然看不清，所以按**区间图贪心着色**分栏：

- 按开始节次升序扫
- 能塞进某个已有 lane（该 lane 上最后一块已结束）就复用，否则开新 lane
- 一组**互相连通的冲突块**共享 `laneCount = maxLane + 1`，宽度才对齐

关键边界（都有单测）：
- **首尾相接不算冲突**（1–2 与 3–4 各占满宽）—— 分错会让整列无故变窄
- **跨天绝不放在一起算**（周一 1–3 与周三 1–3 不冲突）—— 座位聚类踩过同一个坑
- 三块首尾相连（1–2 / 2–3 / 3–4）只需要 2 栏，第 1 和第 3 块复用同一栏

## 四、🔴 本轮抓到的两个真问题

### 4.1 `optString` 对 JSON null 返回字符串 `"null"`

**现象**：周视图上「思想政治理论课Ⅰ」的教室位置赫然写着 `null`（真机截图）。

**根因**：`org.json` 的 `optString(key)` 在值是 **JSON null** 时返回**字面量 `"null"`**，
不是空串。所以链路是：

```
教务 JSON  jx0601mc: null
   → JwApi.parseCoursesJson  o.optString()  → "null"
   → TimetableStore.encode   → 落盘 "null"
   → TimetableStore.decode   → optString() → "null"
   → 界面                    → 显示「null」
```

**这不是脏数据防御**：教务返回的 `jx0601mc` 对思政第 12–15 周**正常就是 null**
（那几周确实没排教室，实机缓存里 34 条中有 2 条如此）。

**修法**：`cleanFieldText()` 把整串等于 `null`/`undefined`（不分大小写）的归一成空串，
**不用 `contains`** —— 否则 `nullroom` 这种正常词会被误杀（有单测钉住这一点）。
`JwApi` 解析与 `TimetableStore.decode` 两处都过，所以**老缓存不用重新拉课表也会自愈**。

### 4.2 测试夹具与真实数据有偏差（更隐蔽）

`TestTimetable.kt` 号称「由真实课表生成」，但拿平板实机缓存（`files/timetable.json`，34 条）
逐条比对后发现 **3 处不一致**：

| 项 | 夹具（旧） | 真实数据 |
|---|---|---|
| 人工智能概论（周一 9–11 节） | 一条 `4–14` | **两条**：`4–10,13,14` + `11,12` |
| 思政（周三 3–4 节） | `4–17` 连续 | **缺第 10 周**（国庆调课） |
| 思政（周二 5–6 节） | **完全缺失** | `良东150教`，仅第 12 周 |

第 3 条是真漏了；第 2 条会让「第 10 周周三有几门课」算错。
已按实机数据校准，现在**零差异（34/34）**，并补了两条断言：

- `第10周周三没有思政课`
- `人工智能概论拆成两段周次后仍只画一块`（覆盖"同门课同节次多周次段"）

> 教训：**夹具是子集不等于夹具是真实数据**。凡是拿真实数据当夹具，就该有一条
> 「夹具 vs 最新实机缓存」的比对手段，否则测试会长期给出虚假的安全感。

## 五、周次锚点手动设置（P1 的一半）

`Timetable.DEFAULT_FIRST_WEEK_MONDAY = "2026-09-07"` 是写死的常量。
换学期不改，`weekOf` 会静默算错 —— 首页只有一个倒计时错，**周视图是整张表全错**。

自动化的方向（从教务首页读「第 X 周」）还没做，但先给了**手动保险**：

- 周视图底部常驻一行 `周次锚点 2026-09-07 · 改`
- 点开是内联输入框 + 保存/取消（**不弹窗**，符合项目一贯风格）
- `Timetable.validateFirstWeekMonday` 校验两条：能解析成 `yyyy-MM-dd`、**必须是周一**
  - 填成周二不抛异常，只会让整学期每门课错一天 —— 这种静默错误必须在入口拦住
  - 错误信息直接显示在输入框下方，输入框变红
- 保存成功后 `pinnedWeek` 归位到「跟随今天」（旧的手动翻周意图已失效）
- 实测：填 `2026-09-08` 被拒并提示「2026-09-08 是周二，首周锚点必须是周一」，且**没有写进 prefs**

## 七、已知取舍与遗留

**取舍**
- 课程颜色按课名 `Math.floorMod(hashCode, 8)` 稳定散列到 8 色。没用 `abs()` ——
  `hashCode` 可能是 `Int.MIN_VALUE`，`abs` 溢出为负数直接下标越界。
- 色板整体偏淡（暖白纸面风格），所以每块左侧加 **3dp 实色竖条**做识别；
  实测不加竖条时「中医基础学（琥珀）」和「正常人体学Ⅰ（红）」几乎分不出来。
- 单节课（46dp）放不下教室，只显示课名；详情靠点开底部卡。

**遗留**
1. **周次锚点自动化**仍未做 —— 现在靠用户手动改。方向：教务首页 / 学生课表页找权威「当前第 X 周」。
2. **周视图不能横向对比整学期**（只能一周一周翻）。若要「学期总览」需另做缩略图。
3. **没有"跳到指定周"**，只能 ‹ › 一格一格点（范围最大 17 周，实际可忍受）。
4. 周末列规则是「整学期有没有周末课」，如果有周末课就永远显示 7 列 —— 手机上是 7 列，会偏挤（未实测）。
5. 未处理**调课/停课通知**（教务里存在但没接口），周视图只反映课表的静态排课。
6. 「思想政治理论课Ⅰ」里的罗马数字 `Ⅰ`（U+2160）在部分字体下渲染得像 `I`/`！`，未做字形替换。
