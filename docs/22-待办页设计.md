# 22 · 待办页设计（完整页）

> 版本 **v1.0** · 2026-11-24 · 上游：[`docs/21`](21-首页设计.md) §6 待办模块
>
> 首页只放"未完成前 3 条"的摘要；本文定义点「查看全部」之后的**完整待办页**。
> 功能语义照 `mini-apps/DueDo`，结构与配色按本项目蓝白金与 4 Tab 导航调整。

---

## 0. 与 DueDo 的结构差异（先记住）

| 项 | DueDo | ubcm（本文） |
|---|---|---|
| 导航 | 独立 App，底部三页签：待办 / 已完成 / 设置 | 首页下钻的 **L3 页**，带返回 |
| 分类 | 三个页签 | **两个分段**（待办 / 已完成）+ 右上角「⋯」菜单 |
| 设置 | 独立页签 | 收进「⋯」菜单（清空已完成 / 清空全部） |
| 编辑器 | 独立路由 | 同页 push 的 **L4 页** |

---

## 1. 入口与返回

- 入口：首页「待办」区块右上角「查看全部」。
- 返回：左上角 `‹` 或系统返回手势 → 回首页，**保留列表滚动位置**。

| 区块 | 规格 |
|---|---|
| 顶栏 | 高 56dp；左 `‹` 返回 24dp；标题"待办" `h2` 20sp；右"⋯"24dp（点开菜单） |
| 日期 | 标题下 `caption` 13sp `text-3` |
| 分段 | 胶囊分段（docs/18 §8.10）：`brand-700` 选中底/白字，未选中白底 `text-2`；两项等宽 |
| 列表 | 卡片规则完全复用 docs/21 §6.2~6.8（勾选框/进度条/DDL/完成动画/子待办） |
| 底部按钮 | 距底 16dp + 安全区，全宽、44dp 高、`brand-700` 底白字、12dp 圆角；文字"＋ 添加待办" |
| 列表底部留白 | 按钮高度 + 24dp，避免最后一条被压 |

### 2.1 排序（照 DueDo，界面层不自己排）

1. 距 DDL **≤24h（含已过期）**置顶；
2. 无 DDL 的其次；
3. 其余按 DDL 由近到远；
4. 组内按 DDL / 创建时间升序。

### 2.2 底部固定按钮 vs 列表末尾按钮

采用**底部固定**（不随列表滚走）——待办列表可能很长，按钮要始终可达。

## 3. 已完成页（同页分段切换）

| 项 | 规格 |
|---|---|
| 列表 | 按完成时间倒序（最近完成在最上） |
| 卡片 | 整体灰化：文字 `text-3`、勾选框为已勾选态（`success` 描边 + 对勾） |
| 右侧 | 右下角"撤销"图标 20dp（↩），点击 `restore(id)` → 回到待办 |
| 次要信息 | "11/24 完成任务" `caption` 11sp |
| 空态 | "还没有完成的待办" |
| 清空 | 顶栏「⋯」→ 清空已完成（**二次确认**） |

---

## 4. 「⋯」菜单

底部弹层（BottomSheet）三项：

| 项 | 行为 |
|---|---|
| 清空已完成 | 二次确认 → 删除所有已完成 |
| 清空全部待办数据 | 二次确认（红色危险字）→ 清空待办 + 已完成 |
| 关于待办 | 一句话说明"数据仅存本机" |

## 5. 编辑页（L4）

```
┌─────────────────────────────────────┐
│ 取消   新建待办              保存   │
├─────────────────────────────────────┤
│ ┌─────────────────────────────────┐ │
│ │ 待办内容（必填，多行）           │ │
│ └─────────────────────────────────┘ │
│ ┌─────────────────────────────────┐ │
│ │ 备注（选填，多行）               │ │
│ └─────────────────────────────────┘ │
│ DDL                                 │
│ ┌─────────────────────────────────┐ │
│ │ 2026-11-24 20:00                │ │  ← 文本输入
│ └─────────────────────────────────┘ │
│ 子待办                              │
│ ┌───────────────┐ ┌──┐              │
│ │ 麻黄汤         │ │× │              │
│ └───────────────┘ └──┘              │
│ ┌───────────────┐ ┌──┐              │
│ │ 桂枝汤         │ │× │              │
│ └───────────────┘ └──┘              │
│ ＋ 添加子待办                        │
└─────────────────────────────────────┘
```

| 字段 | 控件 | 校验 |
|---|---|---|
| 待办内容 | 多行文本输入，自动增高 | 必填，空则保存按钮禁用 |
| 备注 | 多行文本输入 | 无 |
| **DDL** | 文本输入框 + **右侧时钟图标**（20dp）；点时钟弹出**滚轮选择器**（时/分，类似闹钟），选完回填文本框；框内有值时右侧显示 `×` 清除 | **留空 = 不设 DDL**；有内容时格式必须为 `MM-DD HH:mm` 或 `YYYY-MM-DD HH:mm`，否则保存时标红 |
| 子待办 | 每行输入框 + `×` 删除；底部"＋ 添加子待办"新增一行 | 空行忽略 |

### 5.1 DDL 滚轮选择器（点时钟图标触发）

```
┌─────────────────────────────────────┐
│  取消        设置 DDL         完成   │
│                                     │
│        2026-11-24  （点开日历）      │
│                                     │
│          20  :  00                  │  ← 时 / 分 双滚轮
│                                     │
│          ┌───────────────┐          │
│          │   清除 DDL     │          │
│          └───────────────┘          │
└─────────────────────────────────────┘
```

| 项 | 规格 |
|---|---|
| 形态 | 底部弹层，白底，顶角 28dp，高度约 340dp |
| 顶部 | 取消（`text-2`）· 标题"设置 DDL"（`title`）· 完成（`brand-700`） |
| 日期行 | `2026-11-24` 可点，点开日历（复用 `TinyDatePicker`/系统 DatePicker 或自绘） |
| 时间滚轮 | **时 / 分 两列滚轮**（0–23 / 0–59），滚动吸附，选中行高亮 `brand-700` 15sp，上下行 `text-3` 淡出 |
| 完成 | 回填文本框为 `YYYY-MM-DD HH:mm`（今年内可写 `MM-DD HH:mm`） |
| 清除 DDL | 清空文本框 = 不设 DDL |

**保存规则**：
- 内容非空 → 可保存；否则按钮置灰。
- DDL 非空时解析失败 → 输入框描边变 `danger` + 下方红字"格式：2026-11-24 20:00"。
- 保存成功 → 返回列表并滚动到该条（新建）或原位（编辑）。

## 6. 交互补充

| 场景 | 行为 |
|---|---|
| 勾选完成 | 走 docs/21 §6.5 四阶段动画；动画结束才真正完成 |
| 全部子待办完成 | 父任务自动完成（数据层判断，UI 接受它消失） |
| 撤销 | 已完成页右下角 ↩ 恢复；**不做**"已完成后 5 秒内可撤销"的 toast（DueDo 没有，V1 不加） |
| 子待办勾掉 | 留原位变灰 + 删除线，不移入已完成 |
| 列表刷新 | 每秒一个 `now` 状态驱动倒计时，**整个页面共用一个**，不要每条卡片各起协程 |

---

## 7. 数据与持久化

复用 docs/21 §6.8 的 `TodoItem` / `SubTodo` / `DueLevel`。

- 存储：SharedPreferences JSON（key `todos`）。
- 与首页共用同一个 store：首页只读"未完成前 3 条"。
- DDL 分级与倒计时计算抽成一个纯函数（**可单测**），UI 只消费结果。
